# 2.8.1：Extended Note Block 26.1.2 Fabric

在“音域”中选择 **ENB 扩展音域（MIDI 0–127）**，再使用“严格保留”音高。支持普通体积压缩、极限省材复用和毒曲；体积模式可继续选 CPU 或 NVIDIA GPU。

- 本移植基于 [atemukesu/ExtendedNoteBlock](https://github.com/atemukesu/ExtendedNoteBlock)，保留 MIT 许可。它是本项目制作的移植版，不是上游官方新版本。
- 转换后使用 `extendednoteblock:extended_note_block`，每块的音高和音色写在方块实体 NBT 中。不添加 interaction 实体或幽匿脉络，保留原有紧凑电路及尺寸。
- **创造粘贴须保留全部方块实体 NBT。** 只放同一种方块不能还原音高。使用 Litematica 时开启完整 NBT 粘贴，服务器需要相应命令权限；请先用附带测试曲检查粘贴方式。手工配置见每次导出的 `扩展音符盒配置.json`。
- MIDI 音高 = NBS key + 21，支持 0–127；实际 NBS 文件的 key 通常为 0–87，可用整体移调访问范围两端。严格模式遇到超界音或微分音会明确报错；折叠选项仅在超界时按八度折回，微分音按半音取整。
- 本模式使用 `vanillaInstrument` 固定原版 20 种乐器采样，保留 NBS 原版模式的相对音高关系。原模组未设置该字段的音符盒仍使用底座对应的 GM 音色；两种用法可以共存。
- 生成器写入 `oneShot=true`、`holdUntilRelease=false`。红石上升沿触发一次采样，短脉冲断电不会立即截断尾音；不为每个音符逐游戏刻发送音量更新。再次上升沿仍能触发新的声音。
- ENB 自动保留音符力度和音轨音量，乘积映射为 0–127 整数力度；非零最低为 1，零音量省略。旧 NBS 单音符力度默认为 100%。原版/Quinn 模式和声像能力不变。极高低音使用变速，采样长度和音色随之改变；大量同刻声音仍受客户端音频通道上限影响。
- 模板搜索、材料统计、续算缓存分别保留音域模式。不同八度不会被折成同一音高后错误复用；同一个复用音符盒只写一份 NBT。

验证：普通、毒曲和省材三条导出入口；独立读取 5 个投影中的 1,152 个方块实体；跨 7 个投影区域；GPU 候选经 CPU 电路复核；《兰亭序》保留 3,758 个音符，0NF 保留 106,978 个音符并独立回读全部 27 区域的音符盒 NBT；独立 Fabric 世界 480 次边界音触发和 600 次紧凑线路触发，包含存档重启，起音游戏刻与源时序一致。测试不代表每首新导出的整曲都已在游戏中演奏过。

## 默认共同搜索

普通布线、沙子独立音轨和层间压缩由独立任务同时计算，共享当前最小体积方案。层间压缩持续接收普通布线新产生的候选，不等待普通布线结束。不存在先完成一个模板再轮到下一个的阶段顺序。没有沙子或只允许一条输入时，不运行不适用的拆轨任务；Java 1.20.4 自动使用兼容布线。

- 沙子独立音轨：将小鼓与其他乐器分别编排，保留沙子承托，其他音色可使用更短层距。入口同刻启动，前导静音及所有音乐延迟仍计入主体。
- 自动层间压缩：尝试调整同刻音符的位置和层间距；保留沙子及有效支撑。新方案必须通过相同的形状限制和电路检查才可胜出。
- 乐句复用：每次转换开头只分析一次完整歌曲的精确重复乐句，保留音色、音高、时序和事件重数。互不重叠的乐句预计能省至少 20% 音符，且有符合当前计时器的调用时序，才启动复用任务。分析结果供后续搜索重复使用。重复度不是体积收益：控制器、漏斗和内部线路都计入主体，仍要实际更小才采用。复用布局仅有分部检查，不能视为整机复位或实机播放通过。
- **允许沉重核心**：唯一需要手动选择的压缩模板，默认关闭。勾选后增加沉重核心搜索任务，允许替换小鼓沙子底座；不强制最终使用它。关闭后缓存中含沉重核心的候选也不会被选用。

所有任务按真实方块及必要空气的并集衡量体积，体积相同时优先少用方块。保存的是目前找到的最小合格结果，不保证达到全局最小。选择“CPU + NVIDIA GPU”时，普通几何搜索可使用 GPU，同时运行的压缩和电路复核仍使用 CPU。CPU 模式不会启动 GPU 辅助程序。CPU 线程设置分配给各任务；协调与检查仍可能产生少量辅助线程。

## 形状限制与支撑材料

三项都是硬限制，各自可选“不限”，默认保持原来的 1.5、2、40 格：

- **地面长宽差距**：默认“长边最多比短边长 50%”。例如短边 40 格，长边最多 60 格；选 10% 会更接近正方形。提供正方形、10%～700% 等 12 个限制档位及不限。
- **整体形状限制**：默认“最长边最多是最短边的 2 倍”。同时比较长、宽、高，越小越接近方块，越大越允许扁平或细长。提供 1～10 倍共 12 档及不限。
- **中心听音范围**：默认 40 格，表示主体中心到最远角落的距离。提供 12～128 格共 15 档及不限。越小越集中；这不是音量均匀或所有位置都能听清的保证。没有实体试听台。

结构支撑提供圆石、石头、淡灰色羊毛、石英块、铁块、金块及 **16 色混凝土**，共 22 种。只替换结构实体方块；音符盒下面的乐器底座、玻璃线路、绿色入口、沉重核心和漏斗填充物保留各自用途，不因支撑选择改变音色或计时。

## GPU 兼容与回退

需要 Windows NVIDIA CUDA 显卡及兼容驱动，并非所有英伟达显卡都能用。本包内置 NVRTC 12.9（无需另装 CUDA Toolkit），支持的编译架构从计算能力5.0起；实际以驱动初始化、编译与内核加载成功为准。建议使用支持 CUDA 12.9 的 Windows 驱动（576.57或更新且支持你的显卡的版本）。旧驱动的 CUDA 12.x 二进制兼容不等于能加载本包新生成的 PTX。启动时检查显卡计算能力、驱动CUDA版本和NVRTC可用架构；失败会记录原因并继续CPU，本次转换后续普通搜索周期不再重复启动失败的GPU。

选择GPU不保证更快或体积更小：当前只加速普通布局候选，新模板仍使用CPU；GPU 可与 CPU 模板同时运行，但几何候选不足或复核期间可能暂时空闲。报告分别记录请求设备、实际设备、GPU候选数量及错误。

兼容依据：[NVRTC 12.9架构列表](https://docs.nvidia.com/cuda/archive/12.9.1/nvrtc/index.html)、[CUDA 12.9驱动说明](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-toolkit-release-notes/index.html)、[PTX与旧驱动限制](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)。

## 密集和弦

2.4.3取消读取阶段“每组最多28音/小鼓14音”的统一限制。密集和弦自动尝试多条同时启动的和弦总线，每条线路保留绝对起音时刻，不删音、不降低音量、不把和弦拆成琶音。仍受并行线路上限、具体模板信号距离及包围盒约束限制。绿色入口须同刻触发，可用自动外部启动线连接。当前GPU内核处理原有单线路几何，不能处理这类超密和弦；选择GPU模式时会记录原因并自动走CPU拆轨，不启动无用的GPU进程。默认参与的层间压缩搜索也会比较保留沙子及支撑的紧凑混合音轨。

如果某一单线路模板无法容纳和弦，跳过该模板继续比较其他候选；不会因该模板的限制直接判定整首音乐无法转换。新布局仍需实机验证。

## 尺寸与试听

水平长短边比例、三维最大/最小边比例、中心到角点距离都可修改或设为不限。默认1.5、2、40格。搜索不会为了导出而擅自放宽。中心位置是耳位参考，没有建造实体试听台；距离会影响响度。

## 施工与播放

输出包括 `.litematic`、使用说明、材料清单、转换报告和分层预览。音符盒音高、中继器档位包含在投影状态内，手工施工仍需调准。内部空气必须保留，尤其音符盒上方；沙子先搭支撑再放置。

默认自动连接所有绿色入口，向一个总入口接入1红石刻脉冲即可。关闭自动连线时，由玩家自行等延迟连接各入口。试听台不含在投影中。复用方案需依“使用说明”装填漏斗，并等待指定复位时间再启动。投影内有库存NBT，生存施工仍需手动装填。

## 验证范围

《兰亭序》紧凑升层样机42×35×23（X×Z×高）、33810格，3758音符、15564建筑方块；首次和20TPS复播均准确，729个沙子更新后稳定。比此前42×37×23版本体积减少5.41%，少20个方块。无沙子主轨使用圆石强充能起步，沙子轨使用折返玻璃线。主轨占地42×33，沙子轨42×35，所以后者决定整体边界；其他歌曲按实际布局比较。程序会重新生成并检查保存的源文件对应参数，不会向其他歌曲照搬这些音符。

开启沉重核心后，《兰亭序》样机为42×31×21，27342格、14633建筑方块，包含729个沉重核心，1个同步入口；比上述沙子方案体积减少19.13%。在Java 26.1.2中经过底座正常更新，首次及20TPS原地复播均通过3758个音符的时序、音高、音色核对。沉重核心默认关闭，保留沙子时不要勾选。

这些结果是目前已找到且实测的整曲方案，不是全局最小证明。普通新导出只有静态检查，复用新导出只有分部检查；请在空世界验收。

搜索参数缓存保存在输出目录 `.search-cache` 内，用于续算；缓存保存可重建参数，不能把旧的成功标签当新布局的实机验证。

拆轨搜索会给两条轨道分别分配候选生成时间，并为完整装箱留出预算；已有拆轨方案会先尝试替换升层结构。短预算可能只覆盖部分候选，报告明确记录这一点。局部连接缩短不等于整机包围盒缩小，最终按所有轨道、沙子承托及内部线路的并集计量。



## 自动外部启动线（2.4.4）

勾选“自动连接外部启动线”（默认开启），转换结束后自动避让主体，为不同位置、不同高度的绿色入口连接玻璃上升线，并用 1 档中继器补齐延迟。所有原入口接收同刻脉冲，保留歌曲原时序。只向报告标出的一个总入口提供 1 红石刻（2 游戏刻）脉冲；本版不包含按钮脉冲发生器，不能直接输入普通按钮长脉冲。

外部线路在搜索完成后生成，不参与主体体积、长宽高比例、试听半径及尺寸上限计算。界面和转换报告的“主体尺寸”保持原口径；完整投影尺寸另列。Litematica 的整体包围盒必须实际包含外部线路，因而会大于主体尺寸，不能在文件中虚报。所有新增线路材料计入材料清单，预览及坐标使用完整投影原点。共同启动等待时间单独列出，不改变歌曲内部相对起音。

关闭该选项，仍只输出原有绿色同步入口，自行接线。无法安全接入时会明确报错，不移动音乐或删除音符。线路进行无碰撞、同步到达和信号传播检查；实验复用布局只检查外部网络及各自已有分部检查，不将其标为完整实机验证。

2.4.4 外部线验证：19 个静态回归案例覆盖 1/2/4/8 个入口、四种朝向及现有整曲布局。Java 26.1.2 隔离服 100 TPS 测试八个不同高度入口：单脉冲同步通过；3次脉冲、每次间隔8游戏刻，共24次发声通过，各入口累计通电6游戏刻（每次2游戏刻）。仅是启动线路样机验证，不代表所有新导出的整曲实机通过；未进行正常20TPS整曲复播。


## 紧凑启动线（2.4.5）

启动线改为一格横移配一格上升的玻璃折返线路，可在相邻两列间升高。路由按信号距离插入1档中继器增幅，不再每升一格就加一个中继器；只有实际路由延迟差才需要补齐。单入口不绕行、不生成总线，只补上接入红石粉及玻璃支撑。外部线仍不参与主体体积和尺寸限制。

《春节序曲》固定同一主体，外部线从400方块、71个中继器减至100方块、5个中继器，共同启动等待从3.6秒降至0.3秒。主体仍为50×41×47，含线路完整投影从96×62×53减至58×49×47（均为X×Z×高）。这是已检查的具体布局对比，不是任意曲目的保证或全局最小证明。

总入口仍要求1红石刻脉冲。等待上一遍完全结束再启动；输入普通按钮长脉冲或极短间隔连续触发，可能使脉冲合并。更新软件后需重新导出投影，旧投影中的启动线不会自动改变。

2.4.5 验证：31 个静态回归案例覆盖分散与竖直堆叠入口、四种朝向和现有整曲主体。Java26.1.2 隔离服100TPS中，两种八路样机各通过24次发声与同步时序检查；每路三次脉冲累计通电6游戏刻，保持每次2游戏刻。没有进行正常20TPS整曲复播，新整曲投影仍不标记实机通过。


## NBS 层数兼容（2.4.6）

兼容文件声明层数少于实际音符层编号的 NBS（包括旧版 v0）。读取音符后，仍按文件声明的层数读取已有层设置和自定义乐器，完整校验尾部；通过后仅在内存中扩展层表。缺少设置的层按默认音量100%、居中声像、未锁定处理，并在转换记录及报告中明确提示。已有层的音量、静音、声像等设置保持不变。

不改写源 NBS，不合并重复音符，不修改音高、乐器或起音。截断数据、非法字段和无法解释的尾部仍报错。20000个音符的容量限制仍然保留；像0NF.nbs这样的十万音符文件不会擅自删重来绕过限制。

DJ Got Us Fallin in Love.nbs 实例：NBS v0，声明7层、实际用到第13层，共1859个音符。兼容读取保持全部音符，严格音高和时序检查通过。新导出仍需实机验收，不因修复读取而标记实机演奏通过。


## 2.5.1 验证范围

并行启动、手动结束导出、缓存续算、CPU 模式不启动 GPU、22 种支撑的乐器底座保持、低重复度跳过及高重复度启用复用均有回归检查。实际 RTX 3080 上验证 GPU 与 CPU 模板共同运行，并测试 GPU 初始化失败后回退 CPU。

DJ Got Us Fallin in Love 的一次短搜索找到主体 34×23×18（X×Z×高），1859 个音符；此前版本导出为 34×23×20。该结果只说明具体样例的体积改进，不保证每首歌或每次预算都相同。本次版本只做代码、打包、投影读取和静态电路校验，没有进入 Minecraft，也没有进行 20 TPS 原地重播。


## 密集乐句兼容修复（2.5.1）

复用核心目前每个发声时刻最多容纳 20 音。单个乐句超出容量时跳过该复用候选，继续比较普通多路布线及其他适用乐句；多个声部组合后的乐句也重新检查容量。不会删除音符或让整个复用任务因候选不适用而退出。无法生成残余音轨时直接检查下一乐句。


## 稳定进度显示与连续搜索（2.5.2）

普通搜索线程与 GPU 辅助进程持续运行到预算结束或手动导出，不再每 30 秒销毁并重建。模板内部可以继续扩展有限候选集合，但界面统一显示本次转换的累计候选数、总搜索时间和全局最优体积，不显示各任务反复归零的局部计数。状态快照最多每秒两次，界面每次处理消息队列只绘制最新快照；局部任务不再互相覆盖状态栏。只有全局最优改进才追加候选记录。停止、出错或完成状态不会被队列中的旧进度覆盖。

本版本用超过 36 秒的持续 GPU 搜索验证跨过原来的 30 秒边界：普通搜索仅启动一轮，GPU 保持一个会话，累计时间与计数不回退，最优体积不增大。另有隐藏窗口控件回归检查；未操作用户正在运行的窗口。
